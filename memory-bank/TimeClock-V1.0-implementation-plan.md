### 0.1 规范优先级

出现歧义时按以下顺序执行：

1. 本文“V1.0 决策冻结”与“领域不变量”。
2. 本文规定的 API、状态、数据约束和原子任务验收标准。
3. PRD 中明确标为 V1.0 的范围与验收标准。
4. 前端、后端架构文档中的技术约束。
5. 示例、示意图与埋点建议。

发现本文未消解的冲突时，执行 Agent 必须暂停受影响任务，将冲突、候选影响和建议方案交给协调 Agent；不得自行扩大范围。

### 0.2 编号规则

- 需求：`REQ-领域-序号`。
- 决策：`DEC-序号`。
- 实施步骤：`S阶段-责任域-序号`。
- 测试：`TEST-步骤编号-序号`。
- 阶段门禁：`GATE-S阶段`。
- 责任域：`ARC` 架构协调、`API` 接口契约、`DB` 数据库、`BE` 后端、`FE` 前端、`QA` 测试集成、`SEC` 安全、`OPS` 工程与运维。

编号一经分配不得因插入步骤而重排。数据库迁移编号由数据库 Agent 单独登记，且必须记录对应步骤编号。

### 1.2 明确不实施

以下能力不得创建为 V1.0 开发任务：

- 用户名登录、邮箱验证码、找回密码、密码修改、第三方 OAuth。
- 自定义间隔频率、用户自定义补打开关或窗口。
- OCR，包括图片 OCR 和纯图片 PDF OCR。
- 导入取消、重复题目的“覆盖”动作、用户可见回收站。
- PWA、Service Worker、完整离线写队列、自动冲突合并。
- 浏览器推送、邮件、短信、微信通知、WebSocket。
- Redis、RabbitMQ、独立 Worker、对象存储、微服务、GraphQL、BFF、SSR。
- 社区、好友、排行榜、公开分享、协作、支付、第三方自动同步。
- AI 判题、AI 题解、AI 评分、智能分题、周报/月报、题解模板、标签和任务复制。
- V1.1、V1.2、V2.0 版本规划中的其他能力。

埋点属于建议，不作为 V1.0 发布阻塞项；若实施，不得先于核心闭环，也不得记录密码、Cookie、CSRF Token、题解全文或本地文件路径。

## 2. V1.0 决策冻结

| 决策 | 唯一执行规则 |
| --- | --- |
| DEC-01 账号 | V1.0 仅支持规范化邮箱加密码；邮箱唯一，不支持用户名。 |
| DEC-02 认证 | 使用数据库 Session Cookie 和 CSRF，不使用 JWT；服务端是唯一事实来源。 |
| DEC-03 任务状态 | 持久状态为 `draft`、`active`、`paused`、`archived`；结束状态由结束日期派生；删除使用软删除标记。 |
| DEC-04 草稿启用 | 清单任务可先保存为草稿；至少有一条已确认条目且配置有效后才能启用。习惯任务配置有效后可直接启用。 |
| DEC-05 类型切换 | 仅 `draft`、无打卡记录且无已完成条目时允许切换类型；启用后不可切换。 |
| DEC-06 频率 | 只支持 `daily` 和 `weekly`；每周任务至少选择一个星期。 |
| DEC-07 历史冻结 | 每个打卡保存计划目标与规则快照；修改频率、目标、时区只影响生效边界后的未来计划，不改历史。 |
| DEC-08 题解有效性 | 去除空白后仍有效的文字，或至少一张上传成功且仍有效绑定的图片，即可完成；允许两者并存。 |
| DEC-09 清单自动打卡 | 最后一项达到当日目标时，服务端在同一业务事务中自动完成当日打卡，保证任何界面路径下不漏打卡；前端不发送第二次“今日打卡”写请求。完成最后一项后前端弹出完成弹窗并展示“打卡”按钮：点击按钮确认完成并关闭弹窗；若用户直接关闭弹窗，当日打卡同样已为完成状态。 |
| DEC-10 顺延归属 | 未完成条目在下一计划日优先出现；在新计划日完成时只计入新计划，原日期保持部分完成或漏打。 |
| DEC-11 提前完成 | 非当前计划条目提前完成只增加任务总进度，不增加当前计划完成数，也不生成未来打卡；未来分配自动跳过并补题。 |
| DEC-12 补打 | 窗口固定为任务时区下过去三个自然日，不含今天；原因必填；补打更新完成率但不连接、修复或延长连续链。 |
| DEC-13 清单补打归属 | 优先完成目标历史日期仍未完成的原分配条目，不足时按全局未完成序号补足；这些完成只计目标历史日期，不计今天。 |
| DEC-14 时区 | 任务保存 IANA 时区；用户时区仅是新任务默认值。已形成的当前及历史计划不重写，变更从下一个尚未开始的计划日生效。 |
| DEC-15 到期/逾期 | 未完成任务到提醒时间后为“到期”；任务时区 21:00 后为“逾期”。优先级为已完成、逾期、到期、进行中、未开始。 |
| DEC-16 导入状态 | 统一使用 `PENDING`、`PROCESSING`、`REVIEW_READY`、`CONFIRMING`、`COMPLETED`、`FAILED`。 |
| DEC-17 图片与 OCR | JPG/JPEG/PNG 只作私有资料、题目图或题解图；图片及纯图片 PDF 不自动提取题目。 |
| DEC-18 重复处理 | 候选题仅允许跳过、保留新增、合并到已有条目；默认跳过，不允许覆盖。 |
| DEC-19 文件重复 | 同任务内服务端 SHA-256 相同则返回既有文件和批次，不创建新批次、不重复解析。 |
| DEC-20 基础导出 | CSV/JSON 基础导出属于 V1.0；包含任务、条目、题解文字全文与打卡记录；不内嵌图片和原始资料，不泄漏内部磁盘路径或认证信息。 |
| DEC-21 删除 | 用户确认后立即从普通界面隐藏，内部保留 30 天再清理；V1.0 不提供用户回收站。 |
| DEC-22 离线 | 写操作必须联网；仅未提交文字题解可保存在本地，图片刷新后需重新选择。 |
| DEC-23 撤销归属 | 撤销完成的条目视为回到未完成状态，可重新进入未来计划日的自动分配池；原计划日打卡从 completed 回退为 partial，并局部重算连续天数。 |
| DEC-24 补打不可逆 | 补打（makeup）记录提交后 V1.0 不可编辑、不可撤销；普通编辑仅限今天（习惯型当日编辑），历史日期只能走补打规则。 |

## 3. 领域不变量与统一契约

### 3.1 不得破坏的领域不变量

1. 每项业务资源都归属一个用户；任何查询、修改、下载和导出均在服务端校验归属。
2. 同一任务同一计划日期最多一条有效打卡记录。
3. 同一条目不能在同一打卡中重复计数，一次完成事件不能同时计入两个日期。
4. 清单条目没有有效用户题解时不得完成；题库解析不属于用户题解。
5. 查看解析、保存草稿、上传尚未绑定的图片均不得改变完成状态。
6. 完成条目、更新计划进度、改变打卡状态、写审计和保存幂等结果必须保持事务一致。
7. 补打状态不计入连续天数，也不能修复已经断开的连续链。
8. 无计划日跳过且不打断连续链；部分完成或漏打会中断。
9. 已完成条目不会被后续自动分配；提前完成不会生成未来打卡。
10. 重复导入不得覆盖已有条目 ID、完成状态、用户题解或原解析。
11. 历史计划数据不得因后续配置变更而被回溯修改。
12. 所有用户输入按纯文本转义展示；上传文件内容只能作为数据，不能作为系统指令执行。

### 3.2 API 通用约定

- API 前缀固定为 `/api/v1`。
- 成功响应包含业务数据和请求 ID；失败响应包含稳定错误码、用户可理解消息和请求 ID。
- 所有浏览器请求携带 Session Cookie；所有写请求必须通过 CSRF 校验。
- 完成、撤销、习惯打卡、补打、确认导入等防重复写操作必须使用 `Idempotency-Key`，相同键和相同请求重试返回首次结果。
- 任务、题解和导入候选项编辑使用版本号；版本不匹配返回 409 和最新摘要，不自动覆盖。
- 401 表示会话失效；403 表示权限或 CSRF 失败；409 表示冲突；422 表示字段校验失败；429 表示限流；5xx 表示服务错误。
- 日期值采用 `YYYY-MM-DD` 语义且不进行 UTC 重解释；时间戳携带明确偏移量；时区使用 IANA 名称。
- 列表接口必须明确页码、页大小、排序、筛选及稳定顺序；不得依赖数据库默认顺序。
- 私有文件只通过鉴权接口返回，不暴露磁盘相对路径或绝对路径。

### 3.3 技术基线

- 后端：Java 21 LTS、Spring Boot 3.x、Spring MVC、Spring Security、MySQL 8、Flyway、PDFBox 3.x、POI 5.x、OpenCSV、JUnit 5、Mockito。MySQL 集成测试连接协调者（用户）指定的远程 MySQL 8 实例，不使用 Testcontainers 或本地 MySQL；连接信息仅通过环境变量/配置注入，不得写入代码。
- 前端：TypeScript 5.x、React 19、Vite 6.x、React Router 7.x、Ant Design 5.x、TanStack Query 5.x、React Hook Form 7.x、Zod 3.x、原生 fetch、CSS Modules、Day.js。
- 前端测试：Vitest、React Testing Library、MSW、Playwright。
- 部署：一个 Spring Boot 应用、一个 MySQL 实例、一个持久化文件卷；同域 HTTPS。
- `.idea` 中遗留的 JDK 1.8 配置不得成为实施基线；工程和 CI 必须明确使用 Java 21。

## 4. AI Agent 协作规则

### 4.1 角色与唯一所有权

| 角色 | 所有权 |
| --- | --- |
| 协调 Agent（由用户担任） | 决策表、需求追踪、阶段依赖、冲突裁决和门禁审批；负责分发各责任域任务给 AI 执行 Agent，并审阅每个原子步骤的交付报告 |
| API Agent | OpenAPI、DTO 语义、错误码、状态枚举和契约变更 |
| 数据库 Agent | Flyway 编号、表、索引、约束和 MySQL 集成测试 |
| 后端 Agent | 指定领域模块、事务、授权和后端自动化测试 |
| 前端 Agent | 指定 feature、页面、缓存失效和组件测试 |
| QA Agent | 公共夹具、契约校验、Playwright、兼容和验收证据 |
| 安全 Agent | 认证、越权、文件、日志、限流和生产安全复核 |
| 部署 Agent | CI、Compose、反向代理、监控、备份和恢复 |

### 4.2 开工与交接协议

1. 先完成本切片的决策和 API 契约，再允许数据库、后端与前端并行。
2. 一项原子步骤只能有一个主所有者；其他 Agent 只能在约定接口上协作。
3. 根构建文件、路由表、公共 API 客户端、全局枚举、迁移目录和 E2E 公共夹具必须由单一所有者修改。
4. 已合并的 Flyway 迁移不得修改，只能增加修正迁移。
5. 前端可基于冻结契约先写 MSW 测试；后端可基于同一契约先写 API 和数据库测试。
6. 每次交接必须包含：已完成步骤、变更范围、契约版本、已执行测试、结果、未解决问题和下游注意事项。
7. 没有测试证据、测试失败或契约存在未解决差异时，不得把步骤标为完成。
8. 发现范围外需求时记录并拒绝在 V1.0 实现，不得“顺手添加”。
9. 执行节奏（可由用户更改）：默认每个原子步骤完成后暂停，向用户提交该步骤交付报告并等待确认，确认后再进入下一步骤；当用户确认执行方向无误后，可调整为本阶段内连续执行、仅在阶段门禁（GATE）暂停汇报。用户可引用本条调整节奏。
10. 版本控制约定：commit message 使用中文；每个原子步骤完成后单独提交一个 commit；仅在 main 分支上推进，不创建功能分支。

### 4.3 每项步骤的执行方法

每项步骤按以下顺序执行：

1. 阅读需求、决策、依赖和领域不变量。
2. 先建立该步骤规定的失败测试或验收用例。
3. 实现满足用例的最小行为。
4. 增加失败、边界、越权、重复或并发测试中适用的类别。
5. 执行该步骤测试及受影响的已有回归测试。
6. 记录测试证据并交接；不得把测试留给后续步骤补做。

## 5. 阶段依赖与允许并行关系

| 阶段 | 目标 | 前置阶段 |
| --- | --- | --- |
| S0 | 规格、契约、工程骨架和质量门禁 | 无 |
| S1 | 认证、会话、CSRF 和用户隔离 | S0 |
| S2 | 任务生命周期、计划规则和任务页面 | S1 |
| S3 | 学习条目、顺序分配、顺延和提前完成 | S2 |
| S4 | 图文题解、清单完成/撤销和自动打卡 | S3 |
| S5 | 习惯打卡和今日页 | S2；集成时依赖 S4 |
| S6 | 日历、统计、补打和站内提醒 | S4、S5 |
| S7 | 私有文件、后台任务和文件解析 | S1、S2；复用 S4 文件基础时需协调 |
| S8 | 导入校对、拆分合并、去重和确认入库 | S3、S7 |
| S9 | 导出、全链路验收、部署和加固 | S6、S8 |

允许 S4 与 S7 在公共文件契约冻结后并行；S5 可与 S7 并行；S8 的候选校对前端可在 S7 契约冻结后先用 MSW 开发。任何阶段内部均不得绕过契约步骤直接并行修改共享模型。

公共文件基础设施的所有权：`file` 模块的上传、校验、哈希、原子移动、私有下载与存储骨架由后端 Agent 统一所有。S4-BE-02 先建立最小图片上传能力与 `file_assets`（用途 `solution_image`）；S7-BE-01 在其上泛化并扩展 `source_material` 用途与 50 MB 源资料规则。`file_assets` 表由数据库 Agent 在 S4 建立，S7 只做增量迁移，不重建表。

## S1：认证、会话、CSRF 与用户隔离

### S1-DB-01 建立用户与会话模型

- **目标**：持久化用户、会话及其生命周期。

- **实施指令**：建立用户邮箱唯一约束、密码哈希、时区和状态；建立会话令牌哈希、过期、最后访问、撤销和设备摘要字段；禁止保存明文密码或明文会话令牌。
- **测试 TEST-S1-DB-01-01（数据库集成）**：在 MySQL 中并发插入大小写或空白规范化后相同的邮箱，并插入重复会话令牌哈希。
- **预期结果**：每类重复仅允许一条有效记录，敏感明文不出现在表中。
- **完成标准**：迁移通过空库、升级和回滚预案审阅。

### S1-BE-01 实现邮箱注册

- **目标**：创建安全且唯一的用户账号。
- **所有者**：后端 Agent。
- **实施指令**：规范化邮箱；校验密码与确认密码；使用 Argon2id 哈希；统一处理重复邮箱，避免暴露内部异常；应用单实例限流（默认 5 次失败 / 15 分钟 / IP+邮箱，见 3.4）。
- **测试 TEST-S1-BE-01-01（API 正常与边界）**：注册有效邮箱后查询数据库；再用大小写/首尾空白变体、弱密码和不一致确认密码注册。
- **预期结果**：有效注册成功且仅存 Argon2id 哈希；重复邮箱返回稳定冲突，非法密码返回字段错误且不建用户。
- **完成标准**：日志不包含密码或完整请求体。

### S1-BE-02 实现登录与数据库 Session

- **目标**：验证凭据并签发安全 Session Cookie。
- **所有者**：后端 Agent。
- **实施指令**：验证 Argon2id；生成高熵随机会话值，仅保存哈希；设置 HttpOnly、Secure、SameSite=Lax；会话默认 30 天有效并滚动续期（最后访问超过 15 天时续期，见 3.4）；登录失败使用统一消息并限流。
- **测试 TEST-S1-BE-02-01（安全集成）**：分别使用正确密码、错误密码、不存在邮箱和连续超限请求登录，检查 Cookie 属性及数据库会话。
- **预期结果**：仅正确凭据创建一个会话；错误场景不泄漏账号是否存在；超限返回 429；Cookie 不可由客户端脚本读取。
- **完成标准**：日志不记录 Cookie 或会话值。

### S1-BE-03 实现当前用户、登出和续期

- **目标**：支持刷新恢复会话并撤销当前会话。
- **所有者**：后端 Agent。
- **实施指令**：提供当前用户查询；验证会话过期和撤销状态；按规则更新最后访问；登出撤销服务端会话并清除 Cookie。
- **测试 TEST-S1-BE-03-01（会话生命周期）**：登录后查询当前用户、推进固定时钟触发续期、登出后再次访问、再测试已过期会话。
- **预期结果**：有效会话恢复同一用户；续期符合规则；登出或过期后返回 401，旧 Cookie 不再有效。
- **完成标准**：同一用户的其他有效设备会话不被当前登出误撤销。

### S1-BE-04 强制 CSRF 保护

- **目标**：所有会话写请求必须经过 CSRF 校验。
- **所有者**：后端 Agent 与安全 Agent。
- **实施指令**：提供 CSRF Token 获取；要求写请求提交正确 Token；Token 不写日志，不放入持久化前端存储。
- **测试 TEST-S1-BE-04-01（CSRF 安全）**：对代表性 POST、PATCH、DELETE 分别发送缺失、错误和正确 Token，并验证只读请求不被错误阻断。
- **预期结果**：缺失或错误 Token 返回 403 且无数据副作用；正确 Token 正常进入业务校验。
- **完成标准**：安全 Agent 确认不存在被意外排除的业务写路由。

### S1-BE-05 建立资源归属拦截规则

- **目标**：从基础层防止跨用户访问。
- **所有者**：后端 Agent 与安全 Agent。
- **实施指令**：规定所有资源查询必须同时包含资源 ID 与当前用户条件；无归属资源使用不泄漏存在性的响应；下载和导出也遵守同一规则。
- **测试 TEST-S1-BE-05-01（越权）**：创建用户 A、B 及归属 A 的占位资源，让 B 读取、修改和删除。
- **预期结果**：B 无法判断资源是否存在，数据库无变化，审计记录保留请求 ID 而不泄漏内容。
- **完成标准**：该测试模式纳入后续每种新资源的必测模板。

### S1-FE-01 建立统一 API 客户端

- **目标**：集中处理 Cookie、CSRF、请求 ID、超时和错误映射。
- **所有者**：前端 Agent。
- **实施指令**：所有业务请求只能经统一客户端；写请求自动注入内存 CSRF；将 401、403、409、422、429、5xx 和网络错误映射为稳定前端错误；不得记录敏感数据。
- **测试 TEST-S1-FE-01-01（单元/MSW）**：模拟各种响应和网络断开，检查凭据发送、CSRF 注入、错误类型及日志输出。
- **预期结果**：写请求携带 CSRF；网络错误不被映射成登出；日志不含 Token、Cookie 或密码。
- **完成标准**：feature 模块不得直接调用原生 fetch。

### S1-FE-02 实现注册、登录与会话恢复页面

- **目标**：用户可完成认证并在刷新后恢复状态。
- **所有者**：前端 Agent。
- **实施指令**：提供可访问的注册和登录表单、字段错误、加载状态和失败提示；应用启动请求当前用户和 CSRF；受保护路由根据会话状态跳转。
- **测试 TEST-S1-FE-02-01（组件）**：通过 MSW 验证字段错误、错误凭据、成功登录、401 和网络失败；检查键盘提交、标签和焦点。
- **预期结果**：401 跳转登录；网络失败保留当前状态并提供重试；错误后输入不丢失。
- **完成标准**：密码、Session ID 和 CSRF 不进入 localStorage/sessionStorage。

### S1-QA-01 验证多端会话与用户隔离

- **目标**：证明多端同步的认证基础和用户隔离有效。
- **所有者**：QA Agent。
- **实施指令**：使用两个浏览器上下文登录同一账号，再使用第三个上下文登录另一账号；验证刷新、登出和资源隔离。

- **完成标准**：E2E 稳定重复执行且无共享 Cookie 污染。

## 8. 最终 V1.0 验收场景

协调 Agent 必须确认以下每项都有可重复证据：

1. **认证与多端**：注册、登录、刷新恢复、登出；同账号两个浏览器同步；两个用户数据隔离。
2. **任务创建**：创建习惯任务；创建清单草稿；空清单不能启用；清单有条目后可启用。
3. **计划规则**：daily 和 weekly 按任务时区生成；暂停不生成；恢复不回补；结束后不生成；最后目标自动缩减。
4. **顺序和顺延**：每日目标 5 时按序展示 5 项；未完成项下个计划日优先；已完成项不重复。
5. **提前完成**：非今日条目完成后总进度增加，今日计数不变，未来不再分配。
6. **题解**：空白题解不能完成；文字、仅图片、图文均可完成；题库解析不影响状态。
7. **清单自动打卡**：完成最后目标后自动 completed，前端弹出完成弹窗并提供“打卡”按钮，点击或关闭弹窗均保持已打卡状态，且没有第二次清单打卡写请求。
8. **撤销**：5/5 撤销一项后回到 4/5 partial，题解保留，统计和连续天数更新。
9. **习惯打卡**：无目标一键完成；目标 100 实际 80 为 partial；备注必填得到服务端强制。
10. **历史一致性**：今日、详情、日历和统计对完成、撤销、补打显示一致。
11. **连续天数**：连续 3 个计划日为 3；无计划日跳过；漏打中断；补打不修复。
12. **补打**：过去三日内可补且原因必填；第四日、今天、无计划日拒绝；清单条目不跨日期重复计数。
13. **提醒**：提醒时间后 due，21:00 后 overdue，完成后不提示；无外部通知。
14. **PDF**：可提取文本样本支持跨页标题/解析并进入预览；不根据封面题数虚构。
15. **DOCX/CSV**：生成候选、报告错误行、未确认前不创建正式条目。
16. **不支持 OCR**：图片和纯图片 PDF 不自动生成候选，给出明确说明。
17. **文件安全**：50 MB、类型、魔数、路径、私有下载及题解图片 9 张/10 MB 限制有效。
18. **文件去重**：同任务重复文件返回既有批次，不重复解析或增项。
19. **题目去重**：默认跳过；保留新增会追加；合并保留原 ID、完成状态和题解并增加解析版本。
20. **人工校对**：编辑、删除、拆分、合并、低置信度确认和幂等入库有效。
21. **并发**：任务/题解候选旧版本返回 409；完成、撤销、补打和确认重试不重复。
22. **删除与清理**：删除立即隐藏；超过 30 天才物理清理；有效文件不误删。
23. **导出**：CSV/JSON 完整且只含当前用户数据，不含秘密和磁盘路径。
24. **部署恢复**：空环境可部署；重启数据持久；数据库和文件卷备份可联合恢复。
25. **非功能**：性能目标、四类浏览器、移动端、键盘与非颜色状态表达通过。
