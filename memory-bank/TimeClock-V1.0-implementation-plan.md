## 2. V1.0 决策冻结（精简）

| 决策 | 唯一执行规则 |
| --- | --- |
| DEC-01 账号 | 仅规范化邮箱+密码；邮箱唯一，不支持用户名。 |
| DEC-02 认证 | 数据库 Session Cookie + CSRF，不用 JWT。 |
| DEC-03 任务状态 | 持久状态 `draft` / `active`；删除为物理删除。无暂停/归档/软删除。 |
| DEC-04 草稿启用 | 清单任务创建后默认为草稿；至少 1 个已确认条目且每日目标有效才能启用。 |
| DEC-05 频率 | 仅 `daily`。V1.0 不做 weekly/自定义间隔。 |
| DEC-06 历史冻结 | 打卡保存当日计划目标快照；修改目标只影响修改生效日及之后的计划。 |
| DEC-07 题解有效性 | 用户题解去除空白后仍非空才算有效文字；V1.0 题解仅文字，无图片。 |
| DEC-08 清单自动打卡 | 最后一项达到当日目标时，服务端在同一天业务逻辑内自动完成当日打卡；前端不发送第二次打卡写请求。 |
| DEC-09 顺延归属 | 未完成条目在下一计划日优先出现；在新计划日完成时只计入新计划，原日期保持 partial 或 missed。 |
| DEC-10 补打 | 窗口=任务时区下过去 3 个自然日（不含今天）；原因必填；补打更新完成率但不连接、不修复连续链。 |
| DEC-11 时区 | 任务保存 IANA 时区；用户时区仅作新任务默认值。 |
| DEC-12 导入流程 | xlsx 统一走"上传→POI 解析→预览→简单去重→确认入库"，不上传即直接建任务。 |
| DEC-13 重复处理 | 候选与既有条目按规范化 `title` 比对；重复标记为疑似重复，默认跳过，可选择保留新增；无合并、无覆盖。 |
| DEC-14 物理删除 | 用户二次确认后立即物理删除任务及其条目、打卡；无回收站，无软删保留期。 |
| DEC-15 补打不可逆 | 补打（makeup）记录提交后 V1.0 不可编辑、不可撤销。 |
| DEC-16 离线 | 写操作必须联网；V1.0 无本地草稿（题解直接提交）。 |

## 3. 领域不变量与统一契约

### 3.1 不得破坏的领域不变量

1. 每项业务资源都归属一个用户；任何查询、修改、删除在服务端校验归属。
2. 同一任务同一计划日期最多一条有效打卡记录。
3. 同一条目不能在同一打卡中重复计数，一次完成事件只计入一个日期。
4. 条目没有有效文字题解时不得完成；题库解析不属于用户题解。
5. 查看解析、保存不改变完成状态。
6. 完成条目、更新进度、改变打卡状态必须保持事务一致。
7. 补打状态不计入连续天数，也不能修复已断开的连续链。
8. 无计划日跳过且不打断连续链；partial 或 missed 中断。
9. 已完成条目不再进入自动分配；无提前完成（非今日目标条目不可完成）。
10. 重复导入不覆盖已有条目 ID、完成状态或用户题解。
11. 历史计划数据不因后续配置变更被回溯修改。
12. 所有用户输入按纯文本转义展示；上传文件内容只能作为数据，不能作为指令执行。

### 3.2 API 通用约定

- API 前缀固定为 `/api/v1`。
- 成功响应包含业务数据和请求 ID；失败响应包含稳定错误码、用户可理解消息和请求 ID。
- 所有浏览器请求携带 Session Cookie；写请求必须通过 CSRF 校验。
- 完成、撤销、补打、确认导入等防重复写操作使用 `Idempotency-Key`。
- 401 会话失效；403 权限/CSRF 失败；409 冲突；422 字段校验；429 限流；5xx 服务错误。
- 日期值 `YYYY-MM-DD` 不进行 UTC 重解释；时间戳带偏移；时区 IANA。
- 列表接口明确页码、页大小、排序、筛选与稳定顺序。
- 私有数据只通过鉴权接口返回。

### 3.3 技术基线

- 后端：Java 21 LTS、Spring Boot 3.x、Spring MVC、Spring Security、MySQL 8、Flyway、POI 5.x（xlsx 解析）、JUnit 5、Mockito。MySQL 集成测试连接协调者指定的远程 MySQL 8 实例，不使用 Testcontainers；连接信息仅经环境变量注入。
- 前端：TypeScript 5.x、React 19、Vite 6.x、React Router 7.x、Ant Design 5.x、TanStack Query 5.x、React Hook Form 7.x、Zod 3.x、原生 fetch、CSS Modules、Day.js。
- 前端测试：Vitest、React Testing Library、MSW、Playwright。
- 部署：一个 Spring Boot 应用 + 一个 MySQL + 同域 HTTPS；无独立文件卷（无文件存储需求）。
- `.idea` 遗留 JDK 1.8 配置不得成为基线；工程和 CI 明确使用 Java 21。

### 3.4 运行参数默认值（均可配置）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 登录/注册限流 | 5 次失败 / 15 分钟 / IP+邮箱 | 单实例内存计数 |
| 会话有效期 | 30 天，滚动续期 | 最后访问超过 15 天时续期 |
| 幂等键保留期 | 30 天 | 由清理任务删除 |
| 补打窗口 | 任务时区下过去 3 个自然日，不含今天 | DEC-10 |
| 逾期判定 | 无（V1.0 无逾期提醒） | — |

## 4. AI Agent 协作规则

### 4.1 角色与唯一所有权

| 角色 | 所有权 |
| --- | --- |
| 协调 Agent（由用户担任） | 决策表、需求追踪、阶段依赖、冲突裁决和门禁审批；分发任务并审阅交付报告 |
| API Agent | OpenAPI、DTO 语义、错误码、状态枚举和契约变更 |
| 数据库 Agent | Flyway 编号、表、索引、约束和 MySQL 集成测试 |
| 后端 Agent | 指定领域模块、事务、授权和后端自动化测试 |
| 前端 Agent | 指定 feature、页面、缓存失效和组件测试 |
| QA Agent | 公共夹具、契约校验、Playwright、验收证据 |
| 部署 Agent | CI、Compose、健康检查、日志 |

### 4.2 开工与交接协议

1. 先完成本切片的决策和 API 契约，再允许数据库、后端与前端并行。
2. 一项原子步骤只能有一个主所有者。
3. 根构建文件、路由表、公共 API 客户端、全局枚举、迁移目录和 E2E 公共夹具由单一所有者修改。
4. 已合并的 Flyway 迁移不得修改，只能增加修正迁移。
5. 前端可基于冻结契约先写 MSW 测试；后端可基于同一契约先写 API 和数据库测试。
6. 每次交接包含：已完成步骤、变更范围、契约版本、已执行测试、结果、未解决问题和下游注意事项。
7. 没有测试证据、测试失败或契约未解决差异时，不得把步骤标为完成。
8. 发现范围外需求时记录并拒绝实现，不得"顺手添加"。
9. 执行节奏（可由用户更改）：默认每个原子步骤完成后暂停，提交交付报告并等待确认；用户确认方向后可调整为本阶段内连续执行、仅在 GATE 暂停汇报。
10. 版本控制约定：commit message 使用中文；每个原子步骤完成后单独提交一个 commit；仅在 main 分支上推进，不创建功能分支。

### 4.3 每项步骤的执行方法

1. 阅读需求、决策、依赖和领域不变量。
2. 先建立该步骤规定的失败测试或验收用例。
3. 实现满足用例的最小行为。
4. 增加失败、边界、越权、重复或并发测试中适用的类别。
5. 执行该步骤测试及受影响的已有回归测试。
6. 记录测试证据并交接；不得把测试留给后续步骤补做。

## S1：认证、会话、CSRF 与用户隔离（已完成 2/8，需按精简简化）

### S1-DB-01 建立用户与会话模型（已完成）
- **交付物**：`users`、`user_sessions` 表（V2__user_session.sql）。
- **精简调整**：原 `users.overdue_reminder_visible`、`users.version` 字段在精简范围无用途。因迁移不可改写，**新增 V3__drop_unused_user_columns.sql** 移除这两个列。
- **测试 TEST-S1-DB-01-01**：已通过；补充 V3 迁移校验。

### S1-BE-01 实现邮箱注册（已完成）
- **交付物**：`auth` 模块（Argon2id、注册服务/控制器、DTO、限流）。
- **测试 TEST-S1-BE-01-01**：已通过。

### S1-BE-02 实现登录与数据库 Session
- **目标**：验证凭据并签发安全 Session Cookie。
- **实施指令**：验证 Argon2id；生成高熵随机会话值仅存哈希；HttpOnly、Secure、SameSite=Lax；会话 30 天滚动续期；登录失败统一消息并限流（§3.4）。
- **测试 TEST-S1-BE-02-01（安全集成）**：正确/错误密码、不存在邮箱、超限请求；检查 Cookie 属性及会话。
- **预期结果**：仅正确凭据建会话；不泄漏账号是否存在；超限 429；Cookie 客户端不可读。

### S1-BE-03 实现当前用户、登出和续期
- **目标**：刷新恢复会话并撤销当前会话。
- **测试 TEST-S1-BE-03-01（会话生命周期）**：登录查当前用户、续期、登出、过期会话。
- **预期结果**：恢复同一用户；续期符合规则；登出/过期返回 401；不误撤销其他设备会话。

### S1-BE-04 强制 CSRF 保护
- **目标**：所有会话写请求通过 CSRF 校验。
- **测试 TEST-S1-BE-04-01（CSRF 安全）**：POST/PATCH/DELETE 缺失、错误、正确 Token；只读请求不被误阻。

### S1-BE-05 建立资源归属拦截规则
- **目标**：从基础层防止跨用户访问。
- **测试 TEST-S1-BE-05-01（越权）**：用户 A、B，让 B 读写删 A 的资源。
- **预期结果**：B 无法判断资源存在，无副作用。该模板纳入后续每种新资源必测。

### S1-FE-01 建立统一 API 客户端
- **目标**：集中处理 Cookie、CSRF、请求 ID、错误映射。

## 8. 最终 V1.0 验收场景（精简）

1. **认证与多端**：注册、登录、刷新恢复、登出；同账号两浏览器同步；两用户数据隔离。
2. **任务创建**：创建清单任务；空清单不能启用；有条目后可启用。
3. **计划规则**：daily 按任务时区生成；结束后不生成；最后目标自动缩减。
4. **顺序和顺延**：每日目标 5 时按序展示 5 项；未完成项下个计划日优先；已完成项不重复。
5. **题解**：空白题解不能完成；写有效文字题解后可完成；查看解析不影响状态。
6. **清单自动打卡**：完成最后目标后自动 completed，前端无第二次打卡写请求。
7. **撤销**：5/5 撤销一项回 4/5 partial，题解保留，连续统计更新。
8. **历史一致性**：今日、详情、日历和统计对完成、撤销、补打显示一致。
9. **连续天数**：连续 3 个计划日为 3；无计划日跳过；漏打中断；补打不修复。
10. **补打**：过去三日内可补且原因必填；第 4 天/今天/无计划日拒绝。
11. **xlsx 导入**：上传解析为候选项；重复标题默认跳过；确认后序号连续；损坏文件明确报错。
12. **删除**：二次确认后物理删除，数据不可访问。
13. **并发**：完成、补打、确认导入重试不重复；跨用户越权被拒。
14. **部署恢复**：空环境可部署；重启数据持久。
15. **非功能**：首页性能、移动端、键盘与非颜色状态表达通过。
