# 学习打卡系统产品需求文档（PRD）— V1.0 精简版

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 学习打卡系统 |
| 文档版本 | V1.4（精简） |
| 产品定位 | 面向个人刷题打卡的轻量 Web 工具 |
| 目标用户 | 1~10 人的个人/小团队刷题学习 |
| 首期形态 | Web 服务，支持邮箱注册登录 |

## 2. 背景与问题

刷题学习者需要按计划逐题推进，并持续记录进度与连续打卡。V1.0 聚焦单一核心场景：**清单型刷题任务**——导入题目，每天完成 N 道并写下题解，达成目标自动打卡，回顾日历与连续天数。

## 3. 产品目标

1. 用户可创建清单型刷题任务（每日目标 N 道）。
2. 用户通过上传 xlsx 或手工方式录入题目，为每道题写文字题解后标记完成。
3. 每天完成 N 道自动生成当日打卡记录，可查看日历与连续打卡天数。
4. 支持过去 3 天内补打卡，原因必填，不计入连续天数。

## 4. 产品范围

### 4.1 V1.0 包含

- 邮箱+密码注册登录（简化多端：同一账号可在多个浏览器登录）。
- 清单型任务的创建、编辑、启用、删除（物理删除+二次确认）。
- 题目录入：手工新增、批量粘贴、上传 xlsx（固定列→解析→简单去重→确认入库）。
- 每道题填写文字题解后标记完成；未完成自动顺延至下一计划日。
- 每日完成目标 N 道后自动生成当日打卡。
- 打卡日历（月视图）、连续打卡天数、补打（过去 3 天，原因必填）。

### 4.2 V1.0 不包含（明确砍掉）

- 习惯型任务、用户名登录、找回密码、OAuth。
- PDF/DOCX/图片解析、OCR、图片题解、文件私有存储。
- 任务暂停/恢复/归档、软删除回收站、自定义频率、提前完成、手动挑题。
- 浏览器/邮件/短信通知、WebSocket、离线同步、AI 判题、复杂统计报表。
- 完整 CSV/JSON 数据导出。

## 5. 核心概念与规则

| 概念 | 定义 |
| --- | --- |
| 打卡任务 | 一个清单型刷题目标，例如"算法 200 题"，每日目标 N 道。 |
| 学习条目 | 任务中的最小学习单元（一道题）。 |
| 用户题解 | 用户为条目填写的文字，是标记完成该题的必要条件。 |
| 打卡记录 | 某天某任务达成目标后生成的记录，是日历与连续天数的事实来源。 |
| 连续打卡 | 连续计划日完成全部当天计划的天数；无计划日不打断。 |

### 5.1 任务状态

持久状态：`draft`（草稿）、`active`（启用）、`deleted`（物理删除）。

- 创建后默认为 `draft`；至少有 1 个已确认条目且每日目标有效后才能启用。
- `active` 任务参与每日计划；删除后立即物理删除（二次确认），不留历史。
- 无暂停、无归档、无软删除。

### 5.2 计划分配规则

1. 任务启用后，每天按条目 `sort_order` 升序自动分配前 N 道未完成、未删除条目作为当日目标。
2. 目标取 `daily_target_count` 与剩余未完成条目数的较小值（最后一天目标自动缩减）。
3. 当天未完成条目自动顺延至下一计划日，优先出现。
4. 条目完成后不可重复计入当日目标；完成后即从自动分配池移除。
5. 条目必须填写非空文字题解后才能标记完成（去空白后仍非空）。
6. 每天完成 N 道后，服务端在同一天业务逻辑内自动生成当日打卡记录（completed），前端不发送第二次打卡写请求。

> 说明：V1.0 无"提前完成"——用户只能完成"今日目标内的题目"（含顺延项）；不在今日范围内的题目不显示完成入口。

### 5.3 打卡状态与连续天数

| 状态 | 含义 |
| --- | --- |
| `completed` | 当日目标达成。计入连续天数。 |
| `partial` | 部分完成但未达标（当天做了但没做完）。中断连续链。 |
| `missed` | 计划日结束无任何完成（漏打）。中断连续链。 |
| `makeup` | 补打完成；计入完成率不计入连续天数，不修复已断链。 |

连续天数规则：仅 `completed` 计入；无计划日跳过不断链；`partial`/`missed` 中断；`makeup` 不计且不修复。

### 5.4 补打卡规则（保留）

过去 3 个自然日（任务时区，不含今天）可补打，原因必填；清单型补打需补齐该日目标对应的条目（完成其未完成项或按序补足）；补打标记 `makeup`，更新完成率但不计入连续天数；补打记录提交后不可编辑、不可撤销。

## 6. 功能需求

## 6.1 今日页

- 展示今日任务、今日待完成题目列表、进度（已完成 N / 目标 N）、连续打卡摘要。
- 清单型今日页按序展示今日目标条目；每条可查看题面、填写文字题解、标记完成。
- 达成目标后自动生成打卡记录并展示完成反馈。

## 6.2 创建与编辑任务

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 任务名称 | 是 | 1-50 字符 |
| 任务描述 | 否 | 最多 500 字符 |
| 开始日期 | 是 | 默认当天 |
| 结束日期 | 否 | 不早于开始日期；空表示长期 |
| 计划频率 | 是 | 仅 `daily`（每天）。V1.0 不做 weekly/自定义 |
| 每日完成数量 | 是 | 整数 ≥1 |
| 提醒时间 | 否 | 仅展示，不做推送 |

- 清单任务必须设置每日完成数量，且至少 1 个已确认条目后才能启用。
- 每日完成数量大于剩余条目数时，最后一天目标自动为剩余数量。

## 6.3 学习条目

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标题 | 是 | 例如"第 1 题：两数之和" |
| 内容 | 否 | 题目正文/链接/说明 |
| 解析 | 否 | 题库自带参考答案，仅查看 |
| 序号 | 是 | 决定默认学习顺序 |
| 用户题解 | 完成时必填 | 文字，去空白后非空 |

### 批量导入（xlsx）

1. 支持上传 xlsx 文件，固定列：`title`、`content`、`analysis`、`link`、`order`（缺失可选字段用默认值）。
2. 上传后由后端用 POI 解析为候选项，展示预览（总条数、标题、错误行），用户确认后才写入正式条目。
3. 确认时做简单去重：按 `title` 去空白后规范化，与既有未删除条目重复的标记为疑似重复；默认跳过，用户可选择保留新增。不做合并、不做文件哈希级去重。
4. 确认入库的条目追加到既有未完成条目之后，自动分配新序号。
5. 解析失败或格式错误给出明确错误，不写入任何条目。

### 今日学习条目

- 列表不使用卡片嵌套；每行展示完成圆点、标题、写题解/查看解析入口。
- 题解为空（全空格/仅换行）时不能完成。
- 达成当日目标后自动打卡。

## 6.4 打卡日历与统计

- 月历视图，区分 completed / partial / missed / makeup / 无计划日。
- 连续打卡天数、当前/最长连续天数。
- 过去 3 天内满足补打条件的漏打日期显示"补打"入口。

## 7. 数据模型（精简）

### 7.1 users

| 字段 | 说明 |
| --- | --- |
| id | UUID |
| email | 唯一，规范化（小写+去空白） |
| password_hash | Argon2id 哈希 |
| timezone | IANA 时区（默认 Asia/Shanghai），仅作新任务默认 |
| created_at / updated_at | 审计字段 |

> 去掉 `overdue_reminder_visible`（无逾期提醒需求）与多端乐观锁 `version`（简化）。

### 7.2 tasks

| 字段 | 说明 |
| --- | --- |
| id | UUID |
| user_id | 归属 |
| name / description | 名称/描述 |
| start_date / end_date | 开始/结束日期 |
| schedule_type | 固定 `daily` |
| timezone | IANA |
| daily_target_count | 每日目标 N |
| status | `draft` / `active` |
| created_at / updated_at | 审计 |

### 7.3 learning_items

| 字段 | 说明 |
| --- | --- |
| id | UUID |
| task_id | 归属 |
| title / content / analysis / external_url | 标题/内容/解析/外链 |
| sort_order | 序号，任务内唯一 |
| status | `pending` / `completed` |
| solution_text | 用户文字题解（完成时非空） |
| completed_at | 完成时间 |
| created_at / updated_at | 审计 |

> 去掉 `source_page_*`、`parse_confidence`（无 PDF）、`submission` 独立表与版本历史（简化）。

### 7.4 checkins

| 字段 | 说明 |
| --- | --- |
| id | UUID |
| task_id | 归属 |
| checkin_date | 计划自然日 |
| status | `completed` / `partial` / `missed` / `makeup` |
| planned_count / completed_count | 计划/完成数 |
| makeup_reason | 补打原因 |
| created_at / updated_at | 审计 |

> 唯一约束 `(task_id, checkin_date)`。去掉 `checkin_items` 分配关系表——每日分配通过条目状态惰性计算，不持久化快照。

## 8. 关键流程

### 8.1 创建刷题任务
1. 新建任务，填名称、每日目标 N。
2. 上传 xlsx 导入题目（或手工/粘贴录入）。
3. 预览确认后条目入库，任务具备启用资格。
4. 启用任务，开始每日分配。

### 8.2 完成当天刷题
1. 今日页展示今日 N 道题。
2. 逐题写文字题解并标记完成。
3. 第 N 题完成 → 自动生成当日打卡记录，进度更新。

### 8.3 补打卡
1. 日历选过去 3 天内漏打日期。
2. 填写补打原因，补齐该日目标条目。
3. 标记 `makeup`，更新完成率，不增加连续天数。

## 9. 非功能需求（1-10 人精简）

| 类别 | 要求 |
| --- | --- |
| 性能 | 首页加载 < 2 秒；1 人使用无并发压力。 |
| 安全 | 用户数据按用户隔离；HTTPS；删除二次确认；密码 Argon2id；Session Cookie。 |
| 可访问性 | 表单有标签、键盘可操作、状态不只靠颜色。 |
| 数据一致性 | 同一任务同一天最多一条打卡记录；同一任务内条目序号唯一。 |
| 兼容性 | 近两版 Chrome/Edge/Safari/Firefox；桌面优先，适配移动。 |

## 10. 验收标准（精简）

1. 用户可创建清单任务并上传 xlsx 导入题目，确认后条目可见。
2. 启用任务后今日页按序展示 N 道待完成题。
3. 题解为空时不能完成；写非空题解后可完成。
4. 完成 N 道后自动打卡，今日/详情/日历状态一致。
5. 连续完成 3 个计划日显示连续天数 3；漏打中断；补打不修复。
6. 过去 3 天内可补打且原因必填；第 4 天/今天/无计划日拒绝。
7. 未完成条目顺延至下一计划日优先出现。
8. 重复标题导入被标记为疑似重复，默认跳过。
9. 删除任务二次确认后立即物理删除，数据不再可见。
10. 两个浏览器登录同一账号可同步查看数据。

## 11. 版本规划

| 版本 | 目标 |
| --- | --- |
| V1.0 | 清单型刷题打卡闭环（本版） |
| V1.1+ | 预留：图片题解、PDF/多格式解析、weekly 频率、数据导出、提醒推送 |

## 12. 已确认产品决策（精简）

| 决策项 | 方案 |
| --- | --- |
| 任务类型 | 仅清单型，V1.0 不做习惯型 |
| 题目导入 | xlsx 上传→解析→简单去重→确认；+手工/粘贴 |
| 题解 | 仅文字，去掉图片 |
| 任务生命周期 | 创建/编辑/启用/删除（物理删除+二次确认）；无暂停/归档/软删除 |
| 分配 | 按序分配+未完成顺延+达标自动打卡；无提前完成/手动挑题 |
| 打卡/统计 | 全部保留：打卡记录、连续天数、日历、补打 |
| 删除 | 物理删除（立即+二次确认） |
| 认证 | 邮箱注册登录/Session；简化多端 |
| 用户规模 | 1-10 人，无高并发/集群/复杂运维 |
