# 学习打卡系统产品需求文档（PRD）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 学习打卡系统 |
| 文档版本 | V1.3 |
| 产品定位 | 面向个人学习目标管理与过程记录的打卡工具 |
| 目标用户 | 有持续学习计划、需要按日追踪完成情况的学习者 |
| 首期形态 | Web 服务，支持注册登录与多端同步 |

## 2. 背景与问题

学习计划常因目标过大、每日动作不清晰、过程不可追溯而中断。例如，用户需要完成 200 道题，每天完成 5 道并为每题写题解；又例如背诵英语单词，只需要确认当天是否完成。

现有待办工具通常无法同时覆盖“按数量推进的学习内容”“每个条目的详细作答记录”与“简单的每日习惯打卡”。本产品通过统一任务管理、可配置打卡规则和清晰的进度反馈，帮助用户将长期学习目标拆解为可执行、可复盘的每日行动。

## 3. 产品目标

### 3.1 核心目标

1. 用户可快速创建并管理学习打卡任务。
2. 用户可通过账号登录，在不同设备查看并同步任务、题目、题解与打卡记录。
3. 用户可配置打卡时间、计划频率和每日完成量。
4. 用户可使用两类打卡方式：
   - 清单型打卡：逐项完成学习内容；每题题解为完成打卡的必填项，可按需查看题库自带解析。
   - 习惯型打卡：仅确认当天已完成，不要求逐条记录。
5. 用户可查看任务进度、连续打卡情况和历史记录。

### 3.2 成功指标

| 指标 | 定义 |
| --- | --- |
| 任务创建完成率 | 创建页开始填写后成功保存任务的比例 |
| 日打卡率 | 当日存在计划任务的用户中，至少完成一次打卡的比例 |
| 连续打卡天数 | 用户连续完成当日计划的自然日数量 |
| 清单完成率 | 已完成学习条目数 / 导入学习条目总数 |
| 题解填写率 | 需填写题解的已完成条目中，存在有效题解的比例 |

## 4. 用户与使用场景

### 4.1 用户画像

| 用户类型 | 特征 | 主要需求 |
| --- | --- | --- |
| 刷题学习者 | 有固定题库、按题量推进 | 导入题目、每日分配、逐题提交题解、查看剩余题量 |
| 语言学习者 | 每日背词、阅读、听力等重复习惯 | 定时提醒、一键打卡、保持连续性 |
| 考试备考者 | 同时存在多个课程或阶段计划 | 总览当天任务、识别逾期任务、复盘进度 |

### 4.2 典型场景

1. 用户创建“算法 200 题”任务，设置每天完成 5 题、每日 20:00 提醒、每题必须填写题解。
2. 用户批量上传或粘贴 200 道题目，系统按每日 5 道自动生成当天待完成题目。
3. 用户完成某道题后填写题解并提交，该题才计为完成；当天 5 题均完成后，当日打卡成功。
4. 用户创建“英语单词”任务，设置每日 100 个、每日 08:00 提醒、无需逐条记录；用户完成学习后点击“今日已打卡”。
5. 用户在首页查看今日待办、连续打卡天数、各任务总进度及历史遗漏日期。

## 5. 产品范围

### 5.1 V1.0 包含

- 创建、编辑、暂停、归档和删除打卡任务。
- 配置任务名称、描述、打卡时间、开始日期、频率、每日目标与打卡规则。
- 支持清单型与习惯型两种任务。
- 支持邮箱或用户名加密码注册登录，并通过云端同步用户数据。
- 清单型任务支持手动新增、批量粘贴、CSV 导入和结构化 PDF 题库导入。
- 一个清单型任务支持多次上传 PDF、图片及文档类学习资料，持续补充题目与解析。
- 对多次上传的内容执行文件级与题目级去重，避免重复入库。
- 清单型条目支持题目标题、题目正文、题库自带解析、用户题解、完成状态与完成时间。
- 用户题解支持文字与图片。
- 今日任务总览、任务详情、打卡日历和进度统计。
- 站内到期提示与逾期提示。
- 防重复打卡、补打卡规则和数据留痕。

### 5.2 V1.0 不包含

- 社区、好友、排行榜和公开分享。
- AI 自动判题、自动生成题解或内容质量评分。
- 复杂 Office 文档的版式还原、扫描件 OCR 的高精度人工校正。
- 多人协作、班级/组织管理、支付订阅。
- 与第三方题库、词典或日历的自动同步。

## 6. 核心概念与规则

| 概念 | 定义 |
| --- | --- |
| 打卡任务 | 一个独立的学习目标，例如“算法 200 题”或“英语单词”。 |
| 打卡计划 | 任务在某一自然日需要完成的目标，例如完成 5 道题或完成一次背词。 |
| 学习条目 | 清单型任务中的最小学习单元，例如一道题、一个章节或一组单词。 |
| 打卡记录 | 用户在某一天对某任务完成计划的记录，包含状态、时间和可选备注。 |
| 题库解析 | 从导入资料中提取的参考答案/解析内容，仅用于查看，不作为用户完成打卡的依据。 |
| 用户题解 | 用户为学习条目提交的文字记录，是清单型任务完成单题打卡的必要条件。 |
| 连续打卡 | 连续自然日完成全部当天计划的天数。无计划日不打断连续天数。 |

### 6.1 任务类型

| 类型 | 适用场景 | 当日完成判定 |
| --- | --- | --- |
| 清单型 | 刷题、章节学习、资料阅读 | 完成数量达到每日目标；每个完成条目均需提交有效的用户题解。 |
| 习惯型 | 背单词、听力、阅读、运动式学习习惯 | 用户主动点击“今日已打卡”；可选填写学习量与备注。 |

### 6.2 默认规则

1. 默认时区为用户设备时区；每日统计按本地自然日 00:00 至 23:59 计算。
2. 默认频率为每天，默认开始日期为创建当天。
3. 打卡时间用于提醒，不限制用户只能在该时刻打卡。
4. 清单型任务当天优先分配尚未完成、未被其他日期锁定的条目，顺序按用户设定的条目序号。
5. 清单型任务 V1.0 始终按条目序号自动顺序分配；用户不可手动挑选或打乱当天题目。
6. 当天未完成的清单条目默认顺延至下一次计划日，并优先展示。
7. 清单型任务中，单个条目完成后不可重复计入当日目标。
8. 用户允许提前完成后续已分配或未分配的条目；提前完成立即计入任务总进度，但不提前生成未来日期的打卡完成记录。
9. 任务暂停期间不生成新计划；恢复后从下一计划日继续。
10. 已归档任务仅可查看历史，不可继续打卡。

### 6.3 补打卡规则

V1.0 默认允许补打卡，补打窗口为过去 3 个自然日。补打需填写原因，系统标记为“补打”，不计入连续打卡天数。产品应保留开关，后续可由用户关闭补打功能或调整窗口。

## 7. 功能需求

## 7.1 首页：今日打卡

### 页面目标

帮助用户在打开产品后立即知道“今天该做什么、已完成什么、还差多少”。

### 页面内容

1. 日期与问候语。
2. 今日总览：今日任务数、已完成任务数、待完成任务数、今日整体完成率。
3. 今日任务列表，每项展示：
   - 任务名称与类型；
   - 提醒时间；
   - 今日目标；
   - 已完成数量 / 目标数量；
   - 状态：未开始、进行中、已完成、已逾期、已暂停；
   - 主操作按钮。
4. 连续打卡摘要：当前连续天数、历史最长连续天数。
5. 快捷入口：新建任务、查看全部任务、查看打卡日历。

### 交互规则

| 任务类型 | 主操作 |
| --- | --- |
| 清单型且未完成 | 进入“今日学习条目”页 |
| 清单型且已完成 | 查看当天记录 |
| 习惯型且未打卡 | 点击“今日已打卡”，可选填写学习量与备注 |
| 习惯型且已打卡 | 查看或编辑当天备注 |

## 7.2 创建与编辑任务

### 基础信息

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 任务名称 | 文本 | 是 | 1-50 个字符，例如“算法 200 题”。 |
| 任务描述 | 多行文本 | 否 | 最多 500 个字符。 |
| 任务类型 | 单选 | 是 | 清单型 / 习惯型。创建后允许切换，但需二次确认。 |
| 图标/颜色 | 选择 | 否 | 用于任务列表识别。 |
| 开始日期 | 日期 | 是 | 默认为当天。 |
| 结束日期 | 日期 | 否 | 不早于开始日期。为空表示长期任务。 |
| 计划频率 | 单选/多选 | 是 | 每天、每周指定日期、自定义间隔。V1.0 优先支持每天和每周指定日期。 |
| 打卡提醒时间 | 时间 | 否 | 支持一个提醒时间。 |
| 时区 | 下拉选择 | 是 | 默认设备时区。 |

### 清单型专属配置

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 每日完成数量 | 数字 | 是 | 整数，最小 1。 |
| 条目总量 | 系统计算 | 否 | 由导入/新增条目数量计算。 |
| 用户题解 | 固定规则 | 是 | 清单型任务每题均必须提交用户题解，不提供关闭开关。 |
| 条目内容导入方式 | 选择 | 是 | 手动新增、批量粘贴、CSV 导入、PDF 题库导入。 |
| 条目排序 | 固定规则 | 是 | V1.0 按导入后确认的序号升序自动分配。 |
| 允许提前完成 | 开关 | 是 | 默认开启。提前完成立即计入任务总进度；未来计划日仍按剩余条目重新计算。 |

### 习惯型专属配置

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 每日目标单位 | 文本 | 否 | 例如“个”“分钟”“页”。 |
| 每日目标值 | 数字 | 否 | 例如 100 个单词、30 分钟。为空时仅记录是否打卡。 |
| 打卡备注是否必填 | 开关 | 是 | 默认关闭。 |

### 保存校验

1. 任务名称、开始日期、频率和任务类型缺失时不可保存。
2. 清单型任务必须设置每日完成数量，且至少存在 1 个学习条目后才能启用。
3. 若每日完成数量大于剩余条目数，最后一个计划日的目标自动调整为剩余数量。
4. 切换任务类型时，若已有历史记录，应告知可能影响后续统计，历史记录不删除。

## 7.3 清单型任务与学习条目

### 条目字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 条目标题 | 是 | 例如“第 1 题：两数之和”。 |
| 条目内容 | 否 | 题目正文、链接、学习要求或补充说明。 |
| 题库解析 | 否 | 从 PDF 或其他资料中提取的参考答案。存在时才显示“查看解析”。 |
| 外部链接 | 否 | 可跳转题库、文档或视频页面。 |
| 序号 | 是 | 用于确定默认学习顺序。 |
| 状态 | 是 | 未开始、已完成。 |
| 用户题解 | 是 | 用户自行撰写的解题思路、答案或学习总结。 |
| 用户题解图片 | 否 | 可上传图片作为题解补充，支持与文字同时提交。 |
| 完成时间 | 系统生成 | 条目成功完成时写入。 |

### 批量导入

1. 支持将每行作为一个条目进行粘贴导入。
2. CSV 至少支持 `title`、`content`、`analysis`、`link`、`order` 列；缺失字段采用默认值。
3. 导入前展示预览、总条数和错误行；用户确认后才写入。
4. 导入后自动分配序号，不覆盖已有条目，除非用户选择“覆盖导入”。
5. 任务支持多次导入资料；新增内容追加到现有条目之后，并重新生成未完成部分的学习顺序。
6. 存在历史打卡记录的任务，不允许直接删除已完成条目；可归档条目或要求二次确认。
7. PDF 导入必须走“上传 - 解析 - 预览校对 - 确认入库”流程，不能在上传后直接创建任务。

### 今日学习条目

1. 系统展示当日计划条目、已完成条目和剩余数量。
2. 用户点击条目进入详情，填写用户题解后点击“完成本题”。
3. 用户题解为空、全空格或仅换行时不可完成。
4. 用户可撤销条目完成状态；若导致当日完成数低于目标，当日任务状态回退为“进行中”。
5. 用户可查看和完成非今日条目。提前完成立即计入任务总进度；若完成的是未来已分配题目，该题在未来日期不再重复出现。
6. 当日目标全部完成后，系统自动生成当日打卡记录并展示完成反馈。

### 今日清单打卡页（V1.0 核心页面）

页面以题目列表为主，不使用卡片嵌套。每个题目为一行，行间以细分割线区隔，结构与示意图一致：

| 区域 | 展示与交互要求 |
| --- | --- |
| 完成圆点 | 位于左侧；未完成为空心圆，完成后显示勾选状态。点击不直接完成本题，必须先提交用户题解。 |
| 题目标题 | 位于主内容区，最多显示两行，超出省略；点击标题可展开题目正文。 |
| 难度标签 | 可选字段，显示简单/中等/困难；PDF 未识别到难度时不展示。 |
| 查看解析 | 仅当该题 `analysis` 非空时显示。点击后以抽屉或弹窗查看题库解析，不改变完成状态。 |
| 写题解 | 未完成题始终显示。点击进入题解编辑页或弹窗；保存有效用户题解后可点击“完成本题”。 |
| 已完成状态 | 完成后显示“已完成”与完成时间，保留“查看解析”和“查看/编辑题解”入口。 |
| 今日打卡按钮 | 固定在列表底部，文案显示“今日打卡（还差 n 题）”；仅当当天所有题目均已完成时可点击并完成打卡。 |

题解编辑区应至少包含“我的题解”多行文本输入、图片上传、保存草稿、完成本题四个操作。用户可仅上传图片，或提交文字与图片组合；提交后需至少包含有效文字或一张有效图片。题库解析与用户题解必须视觉和数据隔离，避免用户误将查看解析视为已完成学习。

### PDF 题库解析与导入

#### 输入范围

1. V1.0 支持带可提取文本层的 PDF、JPG、JPEG、PNG 图片，以及 DOCX 文档；单文件大小上限 50 MB，PDF 页数上限 500 页。
2. PDF 和 DOCX 用于提取题目标题、题目正文和题库解析；图片用于补充资料、题目截图或用户题解图片。
3. 扫描件、纯图片 PDF 或文本提取质量过低的文件，系统提示“暂不支持自动解析”，允许作为原始资料保存，并引导用户使用 OCR 后重试或改用 CSV 导入。
4. 上传文件内的文字仅作为题库数据来源，不执行其中的任何指令、链接动作或操作要求。

#### 结构化解析目标

导入后，每个条目至少生成 `题目标题`；若能识别到紧随其后的解答内容，则写入 `题库解析`。题目与解析均保留来源页码和原始文本片段，供预览校对和问题追溯。

| 字段 | 解析要求 |
| --- | --- |
| title | 提取问题标题，去除页眉、页脚、网站推广和无意义空白。 |
| content | 提取标题下、解析正文前的题干补充内容；无独立题干时为空。 |
| analysis | 提取该题答案/解析正文；未识别到有效内容时为空。 |
| source_page_start/end | 记录题目及解析覆盖的 PDF 页码。 |
| parse_confidence | 解析置信度，用于提示用户重点校对。 |

#### 样本 PDF 适配规则

针对《Java 热门面试题 200 道速记通关版》，解析器以全文阅读顺序处理：题目标题通常为以中文问号或英文问号结尾的独立问句，题目标题后的连续正文视为该题解析，直到下一个识别出的题目标题出现。解析必须跨页连续处理，因此不可假设“一页一题”。导入时应过滤封面、页眉页脚、网址推广等非题目内容。

由于不同 PDF 的标题格式可能不同，系统不能只依赖“问号”规则。解析器应按以下优先级识别边界：

1. 文档样式或目录结构提供的标题层级；
2. 显式编号模式，如 `1.`、`1）`、`Q1`、`问题 1`；
3. 独立问句及其后的连续正文模式；
4. 用户在预览页手动合并、拆分、编辑或删除条目。

#### 导入预览与人工校对

1. 系统展示“已识别题目数、含解析题目数、无解析题目数、低置信度条目数”。
2. 预览表逐条展示序号、题目标题、解析摘要、来源页码和置信度。
3. 用户可在确认前编辑标题和解析、删除误识别条目、拆分一条为多题、合并多条为一题。
4. 未识别到解析的条目仍可导入，但其列表中不显示“查看解析”。
5. 用户确认导入后，生成学习条目；此后 PDF 原文不再参与日常打卡判定。
6. PDF 封面标称题数仅作为参考，实际入库数量以用户确认的预览结果为准；系统不得为了匹配标称数量虚构题目或解析。

#### 多次上传与去重

1. 一个任务可在创建后持续上传新的题库文件、题目截图或补充资料；每次上传均生成独立导入批次，可查看批次来源、时间、文件与入库结果。
2. 文件级去重：计算文件哈希值。相同任务下若上传文件哈希一致，提示“该文件已上传”，默认不重复解析；用户可查看既有批次。
3. 题目级去重：对标题、正文和解析进行标准化处理（去除空白、页眉页脚、常见编号和格式差异）并计算内容指纹；与已有条目高度相似时标记为疑似重复。
4. 对疑似重复条目，预览页必须展示“保留新增”“合并到已有题目”“跳过”三个选项；默认选中“跳过”，不得自动覆盖用户题解、完成状态或原有解析。
5. 合并时保留原题目 ID、完成状态和用户题解；新解析作为补充解析写入版本记录，供用户选择查看。
6. 每次确认导入后，新建且未重复的条目排在既有未完成条目之后，不影响已生成或已完成的历史记录。

#### 解析失败处理

| 场景 | 系统处理 |
| --- | --- |
| 未识别到任何题目 | 不允许确认导入，提示手动标记题目或改用 CSV。 |
| 识别到题目但无解析 | 可导入，条目不展示“查看解析”。 |
| 题目/解析边界不可信 | 标记低置信度，要求用户在预览中确认后才可导入。 |
| PDF 加密、损坏或无法提取文本 | 给出明确失败原因，不保存半成品任务。 |

## 7.4 习惯型任务打卡

### 页面与操作

1. 用户进入任务详情或首页任务卡，点击“今日已打卡”。
2. 若设置每日目标值，弹窗展示实际完成量输入框，默认带入目标值。
3. 用户可填写备注，例如“复习 Unit 3-4”。
4. 若开启备注必填，备注为空不可提交。
5. 提交成功后生成当日打卡记录；当日可编辑实际完成量和备注。

### 状态判定

| 条件 | 打卡状态 |
| --- | --- |
| 未创建记录且提醒时间未到 | 未开始 |
| 未创建记录且提醒时间已过 | 待完成/逾期提示 |
| 实际完成量达到目标值，或未设目标值且已提交 | 已完成 |
| 实际完成量低于目标值 | 部分完成，默认不计入连续打卡 |

## 7.5 任务详情与统计

### 任务详情

1. 展示任务名称、类型、状态、创建日期、频率、提醒时间及任务描述。
2. 展示总体进度：
   - 清单型：已完成 / 总条目、剩余条目、预计完成日期；
   - 习惯型：累计打卡天数、本月完成天数、目标完成率。
3. 展示当前连续打卡天数、最长连续打卡天数。
4. 展示按月打卡日历，区分已完成、部分完成、补打、漏打和无计划日。
5. 展示最近打卡记录，支持按日期查看详情。
6. 提供编辑、暂停/恢复、归档、删除操作。

### 预计完成日期

清单型任务预计完成日期 = 从下一计划日起，按照任务频率和每日目标数量，完成剩余条目所需的最后一个计划日。暂停期间不纳入计算。该日期仅为预估，用户调整计划或补做条目后实时更新。

## 7.6 打卡日历与历史记录

1. 支持按月查看全部任务或单个任务的打卡情况。
2. 点击日期可查看当天各任务的计划、实际完成量、备注、题解摘要和补打原因。
3. 支持筛选：全部、已完成、漏打、补打、部分完成。
4. 过去 3 天内满足补打条件的漏打记录显示“补打”入口。
5. 历史记录修改必须记录最近更新时间；完成记录撤销后同步更新统计与连续天数。

## 7.7 提醒与通知

### V1.0 提醒规则

1. 用户设置提醒时间后，系统在首页和任务页展示“到期提醒”状态。
2. 当天计划未完成时，默认在 21:00 标记为“逾期提醒”；用户可关闭该提示。
3. 已完成当日目标的任务不显示逾期提醒。
4. V1.0 不实现浏览器推送、短信或邮件提醒；用户下次访问 Web 服务时查看站内提醒。
5. 提示内容包含任务名、今日目标和当前剩余量，例如：“算法 200 题：今日还差 3 题。”

## 9. 关键流程

### 9.1 创建清单型刷题任务

1. 用户进入“新建任务”。
2. 选择“清单型”。
3. 填写任务名称、开始日期、频率、提醒时间和每日完成数量。
4. 选择“每题必须填写题解”。
5. 通过粘贴、CSV、PDF、DOCX 或图片资料导入题目。
6. 系统解析资料，用户在预览中校对题目、解析和重复项。
7. 保存任务，系统生成首个计划日。

### 9.2 完成当天刷题打卡

1. 用户在今日页点击“算法 200 题”。
2. 系统展示当天 5 道待完成题目。
3. 用户逐题填写题解并点击“标记完成”。
4. 每完成一题，进度更新为 `已完成 n / 5`。
5. 第 5 题完成后，系统自动标记任务“今日已完成”，生成打卡记录并更新连续天数。

### 9.3 完成背单词打卡

1. 用户在今日页点击“英语单词”的“今日已打卡”。
2. 用户填写实际学习量（可选）和学习备注（可选或按配置必填）。
3. 提交后，系统生成当日打卡记录并更新统计。

### 9.4 补打卡

1. 用户在日历中选择过去 3 天内的漏打日期。
2. 点击“补打”，填写补打原因。
3. 清单型任务需要补齐该日目标对应的学习条目；习惯型任务需要提交实际完成信息。
4. 系统将该日标记为“补打完成”，更新完成率，但不增加连续打卡天数。

## 11. 状态与计算逻辑

### 11.1 清单型每日状态

| 条件 | 状态 |
| --- | --- |
| 当天未到计划日 | 无计划 |
| 已完成数量为 0 | 未开始 |
| 已完成数量大于 0 且小于目标 | 进行中 |
| 已完成数量达到目标，且所有用户题解有效 | 已完成 |
| 计划日结束仍未达到目标 | 漏打/部分完成 |
| 通过补打达成目标 | 补打完成 |

### 11.2 连续打卡计算

1. 从最近一个已完成计划日向前逐日或逐计划日回溯。
2. 只有状态为“已完成”的记录计入连续天数。
3. “补打完成”不计入连续天数，但保留在完成率统计中。
4. 无计划日跳过，不中断连续天数。
5. 任一计划日为“漏打”或“部分完成”时，连续天数在该日中断。

### 11.3 删除与数据保留

1. 删除任务前必须二次确认，并明确告知将删除相关学习条目与打卡记录。
2. 有历史记录的任务优先建议归档，避免误删。
3. V1.0 可采用软删除，保留 30 天恢复窗口；超过窗口后永久清除。

## 13. 异常与边界场景

1. 用户修改每日目标：只影响修改生效日及之后的计划，历史记录保持不变。
2. 用户修改频率：修改生效日后的计划重新计算，已生成的历史计划不回溯改写。
3. 清单型任务剩余条目少于每日目标：最后一天自动以剩余条目数作为目标。
4. 导入重复条目：系统提示可能重复，允许用户跳过、保留或覆盖。
5. 用户撤销当天已完成条目：若当日目标不再满足，应撤销该日“已完成”状态并重算连续天数。
6. 跨时区旅行：以任务配置时区判定计划日和提醒；用户变更任务时区后仅影响未来计划。
7. 离线状态：V1.0 不支持离线打卡、离线上传或自动同步写操作；客户端可暂存未提交的文字题解草稿，联网后由用户主动提交。发生版本冲突时以服务器最新版本为准，并提示用户重新编辑。
8. 任务结束日期已过：不再生成新计划，任务显示“已结束”，仍可查看历史。
9. 同一题目在多台设备同时编辑题解：保留最后一次成功保存的版本，并生成历史版本，避免图片和文字被静默丢失。
10. 用户重复上传同一文件：识别为重复文件后不创建新批次、不增加条目数量。

## 15. 验收标准

### 15.1 创建任务

1. 用户可创建清单型和习惯型任务，并在保存后于任务列表看到该任务。
2. 清单型任务未填写每日完成数量时不能保存。
3. 清单型任务没有学习条目时不能启用。
4. 习惯型任务可在不设置每日目标值的情况下创建。

### 15.2 清单型打卡

1. 用户导入 200 道题后，任务详情正确显示总条目数 200。
2. 设置每天 5 道后，今日页显示 5 道待完成题目。
3. 用户题解为空时，不能将题目标记为完成。
4. 完成 5 道题并填写题解后，系统自动将当天任务标记为完成。
5. 用户撤销其中一道题完成状态后，当日状态回到进行中，进度变为 4/5。
6. 已完成题目不会在后续日期重复进入计划。
7. 有 `analysis` 的题目显示“查看解析”；无 `analysis` 的题目不显示该入口。
8. 用户查看题库解析后，题目仍为未完成，直至提交有效用户题解。
9. 针对可提取文本层的样本 PDF，系统可在预览中识别题目标题及对应解析，并支持跨页解析。
10. 用户可提前完成非今日题目，任务总进度立即增加；该题不会在后续自动分配中重复出现。
11. 用户可多次向同一任务上传资料；重复文件不重复入库，疑似重复题目必须在预览中由用户确认处理方式。
12. 用户可使用文字、图片或文字加图片提交题解；未提供有效文字和图片时不可完成本题。

### 15.3 习惯型打卡

1. 用户可一键完成未设置数量目标的习惯型打卡。
2. 设置每日 100 个单词后，实际完成量为 80 时，状态为部分完成。
3. 开启备注必填时，未填写备注不可提交。

### 15.4 统计与历史

1. 完成当天计划后，首页、任务详情和日历的状态保持一致。
2. 连续完成 3 个计划日后，连续天数显示为 3。
3. 中间出现一个漏打计划日后，后续完成记录重新从 1 开始计算连续天数。
4. 在允许窗口内补打后，日历状态为补打完成，完成率更新但连续天数不增加。
