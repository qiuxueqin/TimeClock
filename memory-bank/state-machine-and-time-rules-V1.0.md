# V1.0 状态机与时间规则冻结（S0-ARC-02 交付物）

> 本文档由 **S0-ARC-02「冻结状态机与时间规则」** 生成。
> 对应测试：**TEST-S0-ARC-02-01（状态表审阅）**。
> 所有者：协调 Agent 与 API Agent。
> 用途：为每类状态列出允许转换、禁止转换、触发者、时间边界和错误结果；作为 API、数据库和前端 Agent 对状态名称与转换达成一致的统一基线。后续各阶段步骤不得引入本文未定义的状态或转换。

## 0. 状态枚举统一命名（跨 DB / API / 前端一致的取值）

| 领域 | 枚举名 | 取值 | 定义来源 |
| --- | --- | --- | --- |
| 任务 | `TaskStatus` | `draft` `active` `paused` `archived` | DEC-03；结束状态由结束日期派生，不新增持久值 |
| 任务 | `TaskType` | `checklist` `habit` | PRD §6.1 |
| 条目 | `ItemStatus` | `pending` `completed` `archived` | PRD §10.2 |
| 打卡 | `CheckinStatus` | `completed` `partial` `missed` `makeup` | PRD §10.5、DEC-12 |
| 导入批次 | `ImportBatchStatus` | `PENDING` `PROCESSING` `REVIEW_READY` `CONFIRMING` `COMPLETED` `FAILED` | DEC-16 |
| 后台任务 | `BackgroundJobStatus` | `PENDING` `RUNNING` `SUCCEEDED` `FAILED` | backend §6.3 |
| 提示状态（派生，非持久） | `ReminderStatus` | `none` `due` `overdue` | DEC-15、REQ-DASH-01 |

> 约定：持久状态使用小写（任务/条目/打卡）；导入与后台任务枚举使用大写（DEC-16 既有命名）；提示状态为按任务时区动态计算，不持久化。

## 1. 任务状态机（TaskStatus）

### 1.1 状态说明

| 状态 | 含义 |
| --- | --- |
| `draft` | 草稿，尚未启用；清单任务创建后默认草稿（DEC-04）；可编辑全部字段，允许切换类型（DEC-05）。 |
| `active` | 已启用；参与计划日生成与打卡。 |
| `paused` | 已暂停；暂停期间不生成新计划，恢复后从下一合格计划日继续（DEC 隐含/REQ §6.2-9）。 |
| `archived` | 已归档；只读，仅可查看历史，不可打卡（REQ §6.2-10）。 |
| `ended`（派生） | 由结束日期派生；不新增持久值，任务状态仍为 `active`，但不再生成新计划（DEC-03）。 |
| `deleted`（软删除） | 软删除标记（DEC-21）；从普通查询与写操作中隐藏，内部保留 30 天。 |

### 1.2 允许转换

| 从 | 到 | 触发者 | 前置条件 / 时间边界 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建） | `draft` | 用户创建 | 清单任务创建后默认 draft；习惯任务配置有效时可直接 active | — |
| `draft` | `active` | 用户"启用" | 清单：≥1 已确认条目且配置有效（DEC-04）；习惯：配置有效 | 422（无条目/配置无效） |
| `active` | `paused` | 用户"暂停" | 任意时刻 | — |
| `paused` | `active` | 用户"恢复" | 恢复后从下一合格计划日继续，不回补暂停期 | — |
| `active` | `archived` | 用户"归档" | 允许任意时刻；有历史时前端优先提示归档 | — |
| `paused` | `archived` | 用户"归档" | 允许 | — |
| `draft` | `archived` | 用户"归档" | 允许 | — |
| `draft`/`active`/`paused` | `deleted`（软） | 用户"删除" | 需二次确认；有历史时返回归档建议摘要（S2-BE-05） | — |

### 1.3 禁止转换

| 禁止 | 原因 / 规则 |
| --- | --- |
| `archived` → 任何非 archived 状态 | 归档只读，V1.0 无"恢复归档"（REQ §6.2-10） |
| `active` → `draft` | 启用后不可回退草稿 |
| `deleted` → 任何状态 | 软删除后不可恢复（V1.0 无用户回收站，DEC-21） |
| 类型切换（DEC-05） | 仅 `draft`、无打卡记录且无已完成条目时允许；启用后禁止 |
| 任何"暂停期间"的生成 | paused 不生成新计划 |
| `ended` 派生后仍生成计划 | 结束日期后不再生成（仅可读历史） |

### 1.4 时间边界与派生规则

- `ended`：任务 `active` 且 `end_date < 今日（任务时区）` → 派生 ended，不生成新计划；任务状态字段仍为 active。
- 暂停：暂停期间跨过的计划日不生成、不补生成；恢复从下一合格计划日继续。
- 归档：归档后所有写操作（打卡、完成、编辑）拒绝。

## 2. 条目状态机（ItemStatus）

### 2.1 状态说明

| 状态 | 含义 |
| --- | --- |
| `pending` | 未开始或未完成，可进入自动分配池。 |
| `completed` | 已完成；必须有有效用户题解（非空文字或 ≥1 张有效绑定图片，DEC-08）；不再进入后续自动分配（不变量 9）。 |
| `archived` | 已归档；不参与分配，不可完成。 |

### 2.2 允许转换

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建） | `pending` | 导入确认 / 手工新增 | 属清单任务 | — |
| `pending` | `completed` | 用户"完成本题" | 有有效题解（DEC-08）；条目归属当前用户；允许提前完成开关（如非当前计划项，DEC-11） | 422（无有效题解）；409（版本冲突）；403（越权/未开启提前完成） |
| `completed` | `pending` | 用户"撤销完成"（reopen） | 幂等键；规则允许（DEC-23） | 幂等重复返回首次结果 |
| `pending`/`completed` | `archived` | 用户归档条目 | 有历史/已完成的条目禁止硬删除，改为归档（S3-BE-01）；V1.0 无条目硬删除 | 422（尝试硬删除已完成项） |

### 2.3 禁止转换

| 禁止 | 原因 |
| --- | --- |
| `archived` → `pending`/`completed` | 归档条目不可回退，不可完成 |
| `pending` → `completed` 无有效题解 | DEC-08，不变量 4 |
| 硬删除 `completed`/有历史条目 | S3-BE-01：改为归档 |
| 条目跨任务关联 | 不变量：条目严格归属其任务（S3-DB-01） |

### 2.4 时间/归属边界

- 提前完成（DEC-11）：非当前计划条目完成 → 总进度 +1，**不**增加今日计数、**不**生成未来打卡；未来分配跳过并按序补足。
- 撤销（DEC-23）：撤销后条目回到未完成，可回分配池；对应打卡从 completed 回退 partial（若不再达标）。

## 3. 打卡状态机（CheckinStatus）

### 3.1 状态说明

| 状态 | 含义 |
| --- | --- |
| `completed` | 当日目标达成（清单完成数达标 / 习惯实际量达标或无目标已提交）。计入连续天数（不变量 7）。 |
| `partial` | 有部分完成但未达标（清单部分完成 / 习惯实际量低于目标）。中断连续链（不变量 8）。 |
| `missed` | 计划日结束未达成且无任何完成（漏打）。中断连续链。 |
| `makeup` | 补打完成；计入完成率但不计入连续天数，不修复已断开的连续链（DEC-12、不变量 7）。 |

### 3.2 允许转换

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建，惰性） | `completed` | 最后一项清单达标时服务端同事务自动完成（DEC-09） | 清单达到当日目标 | 前端不发第二次写请求 |
| （创建，惰性） | `partial` | 用户完成部分条目后计划日结束 | 清单完成数>0 且<目标 | — |
| （创建，惰性） | `missed` | 日结调度（每小时，S6-BE-03） | 计划日结束无记录 | — |
| `partial` | `missed` | 不可（部分完成≠漏打） | — | — |
| `partial` | `completed` | 当日习惯编辑（S5-BE-02） | 实际量改为达标；仅限今天 | 历史日期走补打 |
| `completed` | `partial` | 撤销一项清单（S4-BE-05） | 完成后完成数<目标；幂等键 | — |
| `missed`/`partial` | `makeup` | 用户补打（S6-BE-04/05） | 过去 3 自然日（任务时区，不含今天，DEC-12）；原因必填；原日期为计划日 | 422（第四日/今天/无计划日/空原因） |
| `makeup` | （无） | — | **补打不可逆**（DEC-24）：提交后不可编辑、不可撤销 | — |

### 3.3 禁止转换

| 禁止 | 原因 |
| --- | --- |
| `completed`/`partial`/`missed` → 直接 `makeup` 覆盖历史事实 | 补打不通过覆盖原始历史伪装正常完成（S6-DB-01）；makeup 是独立记录 |
| `makeup` → 任何状态 | DEC-24 不可逆 |
| 同任务同日期第二条有效记录 | 不变量 2：`(task_id, checkin_date)` 唯一 |
| 补打"今天"或第 4 个自然日 | DEC-12 窗口固定过去 3 自然日，不含今天 |
| 无计划日产生打卡 | S3-BE-03：只有 active 且当日符合频率才创建 |

### 3.4 派生：漏打/部分完成结算

- 每小时扫描已过计划日（任务时区）：无记录 → `missed`；有未达标记录 → `partial`；跳过 paused/archived/ended（S6-BE-03）。
- 连续天数规则（不变量 7/8）：仅 `completed` 计入；无计划日跳过不断链；`partial`/`missed` 中断；`makeup` 不计且不修复。

## 4. 导入批次状态机（ImportBatchStatus，DEC-16）

### 4.1 状态说明与转换

```
创建 → PENDING → PROCESSING → REVIEW_READY → CONFIRMING → COMPLETED
                        └──────────────→ FAILED
```

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建） | `PENDING` | 上传成功事务（S7-BE-03） | 同任务同哈希命中时返回既有批次，不创建新批次（DEC-19） | 返回既有 batchId |
| `PENDING` | `PROCESSING` | 后台任务领取（S7-BE-04） | 每 5 秒领取；行锁+SKIP LOCKED | — |
| `PROCESSING` | `REVIEW_READY` | 解析成功（S7-BE-05/06/07） | 生成候选项；未识别到任何题目时不允许确认 | — |
| `PROCESSING` | `FAILED` | 解析失败 | 指数退避最多 3 次；错误摘要受控，不泄漏堆栈/路径 | — |
| `REVIEW_READY` | `CONFIRMING` | 用户确认导入（S8-BE-07） | 校验标题必填、低置信度已确认、重复动作合法；幂等键 | 幂等重试返回首次 |
| `CONFIRMING` | `COMPLETED` | 确认事务成功 | 事务内新增/跳过/合并、统计、审计 | 失败无部分条目，可恢复或 FAILED |
| `REVIEW_READY`/`CONFIRMING` | `FAILED` | 事务失败 | 恢复或标记 FAILED | — |

### 4.2 禁止转换

| 禁止 | 原因 |
| --- | --- |
| `PENDING` → `REVIEW_READY` | 必须经过解析处理 |
| `COMPLETED` → 任何状态 | 批次完成后不可再编辑或确认（S8-FE-03） |
| `FAILED` → `REVIEW_READY` | 失败后需重新上传，不回退成功 |
| 覆盖重复文件为"覆盖"动作 | DEC-18：仅跳过/保留新增/合并，无覆盖 |

### 4.3 解析失败场景（S7-BE-06）

扫描件/纯图片 PDF/加密/损坏/超 500 页 → `FAILED` 或明确不支持语义，不生成虚假候选，不创建正式条目。

## 5. 后台任务状态机（BackgroundJobStatus）

### 5.1 状态说明与转换

```
创建 → PENDING → RUNNING → SUCCEEDED
                 └───────→ FAILED
```

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建） | `PENDING` | 上传事务 | 与 import_batch 同事务创建（S7-BE-03） | — |
| `PENDING` | `RUNNING` | 领取调度（S7-BE-04） | 行锁+SKIP LOCKED，锁定+过期；应用重启可恢复 | — |
| `RUNNING` | `SUCCEEDED` | 解析完成 | 写入候选，批次→REVIEW_READY | — |
| `RUNNING` | `FAILED` | 解析失败 | 指数退避最多 3 次 | 错误摘要受控 |
| `RUNNING`（锁过期） | `PENDING` | 锁过期重领 | 崩溃遗留锁可恢复 | — |

### 5.2 禁止转换

- 同任务同类型同状态重复领取；同一后台任务同一时刻只执行一次（S7-BE-04）。
- `SUCCEEDED`/`FAILED` 不重复执行。

## 6. 提示状态（ReminderStatus，派生，不持久化）

按任务时区与完成情况动态计算（S6-BE-06），优先级：`completed` > `overdue` > `due` > `进行中` > `未开始`（DEC-15）。

| 条件 | 派生状态 |
| --- | --- |
| 当日已完成 | 无提示（completed 优先） |
| 提醒时间后未完成 | `due`（到期） |
| 任务时区 21:00 后未完成 | `overdue`（逾期） |
| 提醒时间未到 | `due` 之前视为未开始/进行中（无 due） |
| 完成状态优先 | 已完成不显示任何到期/逾期提示 |

边界示例：提醒时间晚于 21:00 时，21:00 后仍按 overdue（21:00 是逾期判定时刻，与提醒时间无关）。用户关闭"逾期提示显示偏好"仅隐藏界面展示，不改变领域状态（REQ-USER-01 / S2-BE-07）。

## 7. 时间规则冻结

### 7.1 日期/时区语义（不变量 10、DEC-14）

1. 日期值为 `YYYY-MM-DD`，**不**重新解释为 UTC；计划日与提醒以**任务时区**判定。
2. 时区使用 IANA 名称；用户时区仅作为新任务默认值（DEC-14）。
3. 已形成的当前及历史计划不重写；变更从下一个尚未开始的计划日生效（历史冻结，DEC-07）。

### 7.2 关键时间边界（§3.4 运行参数）

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 逾期判定时刻 | 任务时区 21:00 | DEC-15 |
| 补打窗口 | 过去 3 自然日（任务时区，不含今天） | DEC-12 |
| 会话有效期 | 30 天滚动续期（最后访问>15 天续期） | §3.4 |
| 幂等键保留期 | 30 天 | §3.4 |
| 软删除保留期 | 30 天 | DEC-21 |
| 题解文字草稿保留期 | 30 天 | §3.4 |
| 计划日生成 | 惰性（首次读取/写入/日结） | S3-BE-03 |

### 7.3 计划日生成规则

- 仅 `active`（非暂停、未结束、未归档）且当日符合频率（daily 每日 / weekly 当日为所选星期）的任务生成打卡。
- 目标取 `daily_target_count` 与剩余未完成条目数的较小值（最后计划日目标缩减）。
- 未完成条目按序顺延至下一计划日优先分配（DEC-10）。

## 8. 状态表审阅结论（TEST-S0-ARC-02-01）

对上述每个状态执行一次允许转换与一次禁止转换的纸面走查：

| 领域 | 允许转换走查 | 禁止转换走查 | 唯一结果 |
| --- | --- | --- | --- |
| 任务 | draft→active（清单有条目）✓ | archived→active ✗ 拒绝 | 唯一 ✓ |
| 条目 | pending→completed（有题解）✓ | completed→pending 无题解 ✗ | 唯一 ✓ |
| 打卡 | missed→makeup（3 天内）✓ | makeup→partial ✗ 拒绝 | 唯一 ✓ |
| 导入批次 | REVIEW_READY→CONFIRMING（校验通过）✓ | COMPLETED→CONFIRMING ✗ | 唯一 ✓ |
| 后台任务 | PENDING→RUNNING（领取）✓ | SUCCEEDED→RUNNING ✗ | 唯一 ✓ |
| 提示状态 | 未完成+21:00 后→overdue ✓ | completed→overdue ✗（优先 completed） | 唯一 ✓ |

每个用户操作（创建/启用/暂停/恢复/归档/删除、完成/撤销/补打/编辑、导入确认）在给定输入（类型、状态、日期、时区、题解、配置）下均能落入**唯一**状态；不存在同一输入落入两态或落空的情况。**审计通过（无未决项）。**
