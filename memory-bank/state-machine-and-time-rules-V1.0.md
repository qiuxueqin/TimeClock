# V1.0 状态机与时间规则冻结（S0-ARC-02 交付物，精简版）

> 本文档由 **S0-ARC-02「冻结状态机与时间规则」** 生成，并按精简范围修订（仅清单型，去掉习惯型/暂停/归档/图片/异步解析）。

> 用途：作为 API、数据库和前端 Agent 对状态名称与转换达成一致的统一基线。后续各阶段步骤不得引入本文未定义的状态或转换。

## 0. 状态枚举统一命名（跨 DB / API / 前端一致的取值）

| 领域 | 枚举名 | 取值 | 定义来源 |
| --- | --- | --- | --- |
| 任务 | `TaskStatus` | `draft` `active` | DEC-03；删除为物理删除，无持久 deleted 值 |
| 任务 | `TaskType` | `checklist` | V1.0 仅清单型（PRD §4） |
| 条目 | `ItemStatus` | `pending` `completed` | PRD §7.3 |
| 打卡 | `CheckinStatus` | `completed` `partial` `missed` `makeup` | PRD §7.4、DEC-10 |

> 约定：持久状态使用小写。无导入批次/后台任务状态（V1.0 无异步解析、无文件存储）。

## 1. 任务状态机（TaskStatus）

### 1.1 状态说明

| 状态 | 含义 |
| --- | --- |
| `draft` | 草稿，尚未启用；创建后默认（DEC-04）；可编辑全部字段。 |
| `active` | 已启用；参与每日计划与打卡。 |

### 1.2 允许转换

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建） | `draft` | 用户创建 | 每日目标有效（≥1） | — |
| `draft` | `active` | 用户"启用" | ≥1 已确认条目且配置有效（DEC-04） | 422（无条目/目标无效） |
| `draft`/`active` | （物理删除） | 用户"删除" | 二次确认；立即物理删除任务及关联条目/打卡 | — |

### 1.3 禁止转换

| 禁止 | 原因 |
| --- | --- |
| `active` → `draft` | 启用后不可回退草稿 |
| 删除后任何访问 | 物理删除，数据不再存在（DEC-14） |
| 暂停/恢复/归档 | V1.0 无此状态（DEC-03） |

### 1.4 时间边界

- 结束日期：`active` 且 `end_date < 今日（任务时区）` → 不再生成新计划，但仍可读历史；不引入 ended 持久值。

## 2. 条目状态机（ItemStatus）

### 2.1 状态说明

| 状态 | 含义 |
| --- | --- |
| `pending` | 未完成，可进入自动分配池。 |
| `completed` | 已完成；必须有有效文字题解（去空白后非空，DEC-07）；不再进入自动分配（不变量 9）。 |

### 2.2 允许转换

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建） | `pending` | 手工/粘贴/xlsx 确认 | 属清单任务 | — |
| `pending` | `completed` | 用户"完成本题" | 有效文字题解；条目归属当前用户；属于今日目标或顺延项（无提前完成） | 422（题解空）；403（越权/非今日项） |
| `completed` | `pending` | 用户"撤销完成" | 幂等键 | 幂等重复返回首次 |

### 2.3 禁止转换

| 禁止 | 原因 |
| --- | --- |
| `pending` → `completed` 无有效题解 | DEC-07，不变量 4 |
| 完成非今日/非顺延项 | 无提前完成（不变量 9） |
| 条目跨任务关联 | 条目严格归属其任务 |

### 2.4 时间/归属边界

- 分配：`active` 且当日为计划日时，按序选未完成、未删除条目；目标取每日目标与剩余量较小值。
- 顺延：未完成条目自动带入下一计划日优先出现（DEC-09）。
- 撤销：撤销后回到 pending，可回分配池；对应打卡从 completed 回退 partial（若不再达标）。

## 3. 打卡状态机（CheckinStatus）

### 3.1 状态说明

| 状态 | 含义 |
| --- | --- |
| `completed` | 当日目标达成（清单完成数达标）。计入连续天数（不变量 7）。 |
| `partial` | 有部分完成但未达标。中断连续链（不变量 8）。 |
| `missed` | 计划日结束无任何完成（漏打）。中断连续链。 |
| `makeup` | 补打完成；计入完成率不计连续天数，不修复断链（DEC-10、不变量 7）。 |

### 3.2 允许转换

| 从 | 到 | 触发者 | 前置条件 | 错误结果 |
| --- | --- | --- | --- | --- |
| （创建，惰性） | `completed` | 最后一项达标时自动完成（DEC-08） | 清单达到当日目标 | 前端不发第二次写请求 |
| （创建，惰性） | `partial` | 完成部分条目后计划日结束 | 清单完成数>0 且<目标 | — |
| （创建，惰性） | `missed` | 日结调度（每小时，S6-BE-03） | 计划日结束无记录 | — |
| `completed` | `partial` | 撤销一项（S4-BE-03） | 撤销后完成数<目标；幂等键 | — |
| `missed`/`partial` | `makeup` | 用户补打（S6-BE-04） | 过去 3 自然日（不含今天）；原因必填；原日期为计划日 | 422（第 4 天/今天/无计划日/空原因） |
| `makeup` | （无） | — | **补打不可逆**（DEC-15） | — |

### 3.3 禁止转换

| 禁止 | 原因 |
| --- | --- |
| `partial` → `missed` | 部分完成≠漏打 |
| `makeup` → 任何状态 | DEC-15 不可逆 |
| 同任务同日期第二条有效记录 | 不变量 2：`(task_id, checkin_date)` 唯一 |
| 补打"今天"或第 4 个自然日 | DEC-10 窗口固定过去 3 自然日，不含今天 |
| 无计划日产生打卡 | 仅 active 且当日为计划日才创建 |

### 3.4 派生：漏打/部分完成结算

- 每小时扫描已过计划日（任务时区）：无记录 → `missed`；有未达标记录 → `partial`；跳过未启用/已删除/结束任务（S6-BE-03）。
- 连续天数规则（不变量 7/8）：仅 `completed` 计入；无计划日跳过不断链；`partial`/`missed` 中断；`makeup` 不计且不修复。

## 5. 时间规则冻结

### 5.1 日期/时区语义（不变量 11、DEC-11）

1. 日期值为 `YYYY-MM-DD`，不重新解释为 UTC；计划日以任务时区判定。
2. 时区使用 IANA 名称；用户时区仅作为新任务默认值。
3. 已形成的当前及历史计划不重写；变更从下一个尚未开始的计划日生效（历史冻结，DEC-06）。

### 5.2 关键时间边界（§3.4 运行参数）

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 补打窗口 | 过去 3 自然日（任务时区，不含今天） | DEC-10 |
| 会话有效期 | 30 天滚动续期（最后访问>15 天续期） | §3.4 |
| 幂等键保留期 | 30 天 | §3.4 |
| 计划日生成 | 惰性（首次读取/写入/日结） | S3-BE-04 |

### 5.3 计划日生成规则

- 仅 `active`（未删除、未结束）且当日为计划日（daily）的任务生成打卡。
- 目标取 `daily_target_count` 与剩余未完成条目数的较小值（最后计划日目标缩减）。
- 未完成条目按序顺延至下一计划日优先分配（DEC-09）。

## 6. 状态表审阅结论（TEST-S0-ARC-02-01）

| 领域 | 允许转换走查 | 禁止转换走查 | 唯一结果 |
| --- | --- | --- | --- |
| 任务 | draft→active（清单有条目）✓ | active→draft ✗ 拒绝 | 唯一 ✓ |
| 条目 | pending→completed（有题解）✓ | completed→pending 无题解 ✗ | 唯一 ✓ |
| 打卡 | missed→makeup（3 天内）✓ | makeup→partial ✗ 拒绝 | 唯一 ✓ |

每个用户操作（创建/启用/删除、完成/撤销/补打）在给定输入下均能落入**唯一**状态。**审计通过（无未决项）。**
