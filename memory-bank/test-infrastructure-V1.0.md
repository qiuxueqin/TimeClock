## 2. 约定

### 2.1 固定时钟 / 测试时区

- 领域时间规则（计划日、21:00 逾期、补打窗口、顺延）必须由测试显式指定任务时区与固定时钟，不得依赖服务器默认时区或运行机器日期。
- 后端：使用 `Clock` 注入并在测试中替换固定时钟（S2-BE-06 起）；集成测试用任务时区显式指定。
- 前端：日期展示按用户时区；组件测试用固定 `dayjs`/mock 时钟（S6-FE-01 起）。

### 2.2 测试用户 / 数据隔离

- 测试创建的用户、任务、条目、打卡均为独立测试库数据，运行测试前可重建测试库（`DROP/CREATE time_clock_test`）。
- 用户归属校验（不变量 1）必须在每个新资源类型上复用 TEST-S1-BE-05-01 模板。
- 公共夹具不得包含真实用户邮箱、密码、Session、题解全文或磁盘路径。

### 2.3 文件夹具

- 文件上传/解析测试使用隔离的临时目录（测试专用 `APP_STORAGE_ROOT`），不触碰生产文件卷。
- 黄金样本（Java PDF、DOCX、CSV）置于 `backend/src/test/resources/samples/`，版本化供解析器回归（S7-BE-05）。

### 2.4 数据清理

- 集成测试在前后重建测试库，保证幂等与可重复。
- 单元测试使用内存对象，不连数据库。

## 3. 故障门禁证据（TEST-S0-QA-01-01）

分别放置一个预期通过的示例测试并验证四类测试均被发现；临时制造失败，确认会被 CI 阻断，再恢复：

| 层 | 通过示例验证 | 制造失败验证阻断 | 结果 |
| --- | --- | --- | --- |
| 后端冒烟 | `mvn test` → 1 通过 | （见 S0-OPS-02 故障注入） | ✓ |
| 数据库集成 | FlywayMigrationTests 2 通过 | （失败会抛异常并使 mvn 失败） | ✓ |
| 前端组件 | `npm test` → 2 通过 | 临时 `Home.failing.test.tsx` 使 `npm test` 报 1 failed | ✓ |
| E2E | Playwright 2 通过 | E2E 断言失败会报错 | ✓ |

结论：每一层测试都能被单独执行，失败会产生清晰证据并阻止合并（由 CI 门禁 S0-OPS-02 强制执行）。
